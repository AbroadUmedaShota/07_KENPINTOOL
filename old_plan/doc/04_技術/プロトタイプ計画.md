# 自動検品ツール プロトタイプ計画（PoC）

作成日: 2026-01-04  
最終更新: 2026-01-30

本書は、MVP開発に先立ち「技術リスクの早期潰し込み」と「運用として成立するか」の確認を目的として、プロトタイプ（PoC）の範囲・評価方法・成果物を定義する。

---

## 1. PoCの狙い（何を確かめるか）

### 1.1 UI/操作性

- **キーボード完結**で検品を回せるか（手が止まらないか、マウス不要か）
- NG候補ジャンプ（`N`）と比較（`C`）が運用上の「迷い」を減らせるか
- ハイライト（Evidence矩形）提示が判断の均一化に寄与するか

### 1.2 性能（体感・技術検証）

- **PySide6 + NumPy + Queue/Executor** の構成で、大判図面・多ページでもビュー操作が滞らないか
- バックグラウンドでのページ先読み（プリフェッチ）が、UIスレッドをブロックせずに機能するか
- メモリリーク（特に画像オブジェクト）が発生せず、長時間稼働に耐えうるか

### 1.3 監査・統制

- 「誰が」「いつ」「何を」「どう判断したか」が後追いできるログになっているか
- NG-A例外不可、QLT-05は再スキャンのみ等の制約がUIで破られないか

### 1.4 検知アルゴリズム（Phase 1で必須の核）

- QLT-05（線状ノイズ）の再現性・誤検知/見逃し傾向
- STR-02（重複）の確定精度
- STR-01S/03S（疑い）の「候補提示」と人の確定フローが成立するか

---

## 2. PoCの成果物（最小）

- **動くプロトタイプUI (Pythonアプリ)**
  - Self-contained形式でビルドされた実行ファイル（PyInstaller想定）
  - JPEGフォルダを投入して、3ペイン表示・ショートカットで判定できる
  - NGコードの表示と、QLT-05時の「再スキャンのみ」制約
  - ログ（追記型）とCSV出力
- **PoC評価レポート**
  - 操作性（定性）: 現場レビュー結果
  - 性能（定量）: 1ページ切替、ズーム、比較の応答時間（ミリ秒単位）
  - 検知（定量）: 代表NGコードのPrecision/Recall（Phase 1の対象）

---

## 3. 評価指標（例）

### 3.1 UI

- 連続検品で「マウスに持ち替えたくなる」頻度（0を目標）
- `N`で次NGへ到達するまでのキー数（固定化できるか）

### 3.2 性能

- ページ切替の体感（**100ms以内**の描画完了）
- 大判（A0等）でのズーム/パン操作時に60fps近い滑らかさを維持できるか

### 3.3 検知

- QLT-05: 見逃し最小化を最優先（Recall寄りで閾値設計）
- STR-02: 誤検知を抑えつつ確定可能（Precision/Recallの両立）
- STR-01S/03S: 疑い提示のRecallと、人が確定できる提示情報（前後比較の有効性）

---

## 4. 実施ステップ（段階的）

### PoC-0（UI基盤検証）

- **目的**: アーキテクチャ（MVVM準拠 + Pipeline）の有効性確認
- **実装**:
    - PySide6 + MVVM準拠（signals/slots）スケルトン作成
    - `queue.Queue` + `concurrent.futures` を用いた画像読み込みパイプラインの実装
    - JPEGフォルダ投入、3ペイン表示、ショートカット操作
- **検証**: ページ送りのレスポンス、メモリ推移

### PoC-1（PDF・運用機能）

- PDFページ展開（pypdfium2）
- ログ出力（SQLite）、結果CSV出力
- 現場データを用いた負荷テスト

### PoC-2（検知アルゴリズム）

- STR-02（重複）: pHash/特徴量で類似判定
- STR-01S/03S（疑い）: 画像特徴量＋連続性評価
- QLT-05（線状ノイズ）: 直線検出＋長さ/位置の安定性

---

## 5. テストデータ設計（最低限）

- 正常（OK）: 連番・均一品質
- STR-02: 重複ページを混ぜた案件
- STR-01S/03S: 抜け/入替の疑いが出る案件（真の抜け/順序違いも含む）
- QLT-05: スキャナ由来の縦線/横線（同位置再現があるもの）
- 図面（DWG系）: 細線、圧縮劣化、分割結合ズレが含まれるもの

※ PoCでは機密データを避け、匿名化/マスキング済みデータで実施する。
