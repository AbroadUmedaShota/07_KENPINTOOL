## 1. 前提・重要制約

*   **閉域/ローカル運用**: 外部インターネット接続なしでの動作が必須。
*   **入力データ**: PDFおよびJPEG画像（案件単位、数千ページ規模）。
*   **UIパフォーマンス**: スループット最大化のため、キーボード操作への即応性と、大判画像の高速表示・切り替えが求められる。
*   **ルール適用の強制**: NG-A例外不可などの業務ルールを厳格に適用する。
*   **監査対応**: 操作ログの完全性と改ざん検知性を確保する。

## 2. 推奨構成（結論）

### 2.1 アプリケーション基盤

*   **言語/ランタイム**: **Python 3.12 (64bit)**
*   **UIフレームワーク**: **PySide6 (Qt 6)**
    *   *選定理由*: Windows上での高速描画と、ズーム/パンなどの画像ビューワに必要な機能が成熟しているため。
*   **アーキテクチャ**: **MVVM準拠（Qtのsignals/slotsで疎結合化）**
    *   **方針**: ViewModel層で状態/コマンドを集中管理し、UIロジックを分離する。
    *   **構成管理/ログ**: Python標準ライブラリ（`logging`/`tomllib`/`json`）を基本とし、依存は最小限に抑える。

### 2.2 言語/ランタイム

*   **言語**: **Python 3.12**
*   **配布形態**: **Self-contained (自己完結)**
    *   Pythonランタイムを同梱し、クライアントPCへの事前インストールを不要にする。
    *   展開はZip解凍またはインストーラ（PyInstaller）を想定。

### 2.3 主要ライブラリ選定

| カテゴリ | 推奨ライブラリ | 選定理由 |
| :--- | :--- | :--- |
| **画像処理** | **OpenCV (opencv-python) + NumPy** | Python標準の画像処理スタック。`numpy.ndarray`でゼロコピー連携が可能。 |
| **PDF処理** | **pypdfium2** | PDFiumをPythonから直接利用でき、高速レンダリングが可能。 |
| **ローカルDB** | **sqlite3 (標準ライブラリ)** | 軽量な組み込みDB。監査ログと案件メタデータの管理に最適。 |
| **レポート出力** | **ReportLab** | 画像付きPDFレポートを安定して生成できる。 |
| **設定管理** | **tomllib / json (標準ライブラリ)** | 設定ファイルの読み込みとバージョン管理を軽量に実現。 |

## 3. パフォーマンス最適化戦略（Technical Challenge）

本ツールの肝である「高速な検品体験」を実現するため、以下の技術要素を必須とする。

### 3.1 メモリ管理と高速化（NumPy / memoryview）

*   画像データは`numpy.ndarray`を中心に扱い、コピーを最小化する。
*   OpenCV（`cv2`）との連携はゼロコピーを優先し、必要時のみ明示的に変換する。

### 3.2 非同期読み込みパイプライン（Queue + Executors）

*   画像の「ディスク読み込み → デコード → リサイズ/加工 → UI表示」の工程を、**`queue.Queue` + `concurrent.futures`** でパイプライン化する。
*   UIスレッドをブロックせず、バックグラウンドで次ページの先読み（プリフェッチ）を行い、ユーザーがページを切り替える瞬間には既にメモリ上に画像が用意されている状態を作る。

### 3.3 UI描画最適化（PySide6）

*   `QImage`/`QPixmap`を用いて描画し、必要に応じて`numpy.ndarray`から直接バッファ連携する。
*   ズーム/パン操作中は低負荷表示、静止時は高画質表示に切り替える。

## 5. 代替案と採否理由

### A. Electron / Web技術
*   **判定**: 不採用
*   **理由**: 大判画像の高速描画とメモリ管理において、Webブラウザの制限（メモリ制限、GC挙動）がボトルネックになるリスクが高い。また、ローカルファイルシステムへの大量アクセスにおいてネイティブアプリに劣る。

### B. .NET / WPF
*   **判定**: 不採用
*   **理由**: 検知アルゴリズムの試作/検証をPythonで進める方針と整合させ、UI〜検知までを同一言語で統一するため。
